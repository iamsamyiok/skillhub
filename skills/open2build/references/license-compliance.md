# 许可证合规参考

## 许可证决策表

| 候选许可证 | 内部工具 | 分发软件 | SaaS | 开源自己项目 |
|---|---|---|---|---|
| MIT/BSD/Apache-2.0 | 可用 | 可用 | 可用 | 可用 |
| MPL-2.0 (文件级) | 可用 | 改动文件须开源 | 可用 | 可用 |
| LGPL (库级) | 可用 | 需动态链接 | 可用 | 注意兼容性 |
| GPL-2.0/3.0 | 不分发即安全 | 整体传染 | 可用 | 需选 GPL 兼容 |
| AGPL-3.0 | 可用 | 传染 | 服务端须开源 | 需 AGPL |
| SSPL/BSL/Commons Clause | 逐条读 | 多数禁止商用 | 多数禁止 | 多数禁止 |
| 无 LICENSE | 找作者书面授权 | 禁止 | 禁止 | 禁止 |

## 红线清单（任一命中即淘汰候选或上报用户）

- 候选项目无 LICENSE 文件 = 默认全版权保留，禁止使用
- 分发软件 × GPL/AGPL = 整体传染，不可行
- SaaS × AGPL/SSPL = 服务端须开源，不可行
- 计划使用对方项目名/Logo（商标不随代码授权）
- LICENSE 文件与代码头 SPDX 标识冲突

## 关键细节

- **Apache-2.0**：显式专利授权；分发时须保留 NOTICE 文件内容；修改文件需标注
- **GPL-2.0-only**（如 Linux 内核）与 Apache-2.0 不兼容；GPL-2.0+ 才兼容
- **AGPL**：网络交互也算"分发"，SaaS 场景的隐藏雷
- **BSL**：注意许可证内写死的"变更日期"（到期自动转宽松许可）
- **片段复制**也构成复制：20 行有创造性的代码同样带原许可证进仓库；
  一行功能性 API 调用无表达空间（merger 原则），风险≈0
- **中国司法实践**：数字天堂诉柚子（GPL 传染性获支持）、罗盒 VirtualApp 案
  （违反 GPL 判赔），"国内没人管"不成立
- **AI 生成代码**：与现有开源项目逐字雷同同样构成复制，
  大段算法/协议实现需人工溯源

## 片段复制的边界判断顺序

1. 有无创造性表达？（无 → 低风险）
2. 我的交付会分发吗？（不分发 → GPL 义务未触发；AGPL 除外）
3. 无论如何：来源注释 + 记入 NOTICES（1 分钟消除 90% 风险）
