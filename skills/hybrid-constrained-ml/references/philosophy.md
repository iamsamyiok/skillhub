# 融合哲学：白盒保底 + 黑盒补强

> 思想来源：Cheng Lou 的 **handwired** —— https://github.com/chenglou/handwired
> 本 skill 把它工程化为「规则约束下的机器学习（rcml）」先验，再与 **XGBoost** 残差融合。

## 两条老路各自的硬伤

| 范式 | 优点 | 硬伤 |
|------|------|------|
| 纯规则 / 纯 rcml（白盒） | 可解释、可审计、硬约束永不翻转 | 只能表达你写死的结构（纯加性/单调性），**抓不到交互项、非线性**；死板 |
| 纯 XGBoost / GBM（黑盒） | 自适应、精度高、自动抓交互 | **不可控**：分布外可能给出负存款、超安全上限；不可读、难合规 |

## 融合思路：让各司其职，由护栏缝合

```
        ┌──────────────────── 你相信"一定对"的结构 ────────────────────┐
        │  rcml 白盒先验: 冻结 符号 / 膝点 / 地板 / 上限, 只训幅度系数   │
        └──────────────────────────────┬───────────────────────────────┘
                                       │ 先验预测 y_prior (保结构、保安全)
真实 y ───────────────────────────────┘
   │
   └─► 残差 = y − y_prior  ──►  XGBoost 残差: 抓先验抓不到的复杂面(交互/非线性)
                                       │
        合成 = clip( y_prior + 残差 , floor , cap )
                                       │
                          ┌────────────┴─────────────┐
                    安全地板/上限由 rcml 焊死   精度/灵活由 XGBoost 贡献
```

**一句话**：结构和安全交白盒（rcml），精度和灵活交黑盒（XGBoost），二者用一道 `clip(floor, cap)` 护栏缝合——**无论 XGBoost 怎么训，物理/业务的硬约束永不越界**。

## 四种融合模式（本 skill 落地模式 1+2）

1. **rcml 先验 + XGBoost 残差（加性）** ← 本 skill 主推，`residual_method: xgboost`
2. **安全壳包裹**：任何黑盒模型外面包一层 rcml 的 `clip(floor, cap)`， instantly 获得硬约束
3. **handwired 控制架构 + ML 叶节点**：高层决策树/规则由人写死，叶子用 ML 拟合
4. **自定义损失正则**：把 rcml 的单调/非负作为 XGBoost 的正则项（软约束）

模式 1 是"精度换灵活、结构保安全"的最佳平衡点；模式 2 是给已有黑盒模型** retrofit（后装）**安全约束的最快手段。

## 为什么比"直接堆 XGBoost"好

- **小数据友好**：白盒先验先用领域知识填了"大部分正确结构"，XGBoost 只需学残差，样本需求大幅下降。
- **分布外安全**：纯 XGBoost 在外推区可能崩（负存款/超上限）；融合模型由 `clip` 兜底。
- **可解释**：最终可读规则 = 白盒系数表 + "残差由 XGBoost 修正"，审计时可拆开看。
- **合规友好**：地板/上限/符号域是**结构冻结**的，合规复核只需看 recipe，不依赖权重。
