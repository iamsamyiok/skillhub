# 常见坑（10 条）

1. **把具体数字写进配方**：配方只放"结构"（方向/膝点/边界），幅度交数据。写死数字就失去了"数据校准"的意义。
2. **滥用 `free`**：能定方向的尽量定 positive/negative，free 越多，白盒先验越弱，越退化为纯黑盒。
3. **以为 XGBoost 残差会自动安全**：残差本身**不**保证边界；安全来自 `clip(floor,cap)` 护栏。务必在审计里跑边界扫描确认。
4. **缺 xgboost 却期望残差生效**：未装时模型**静默降级**为纯白盒（只在训练时打印 warn）。上线前确认 `pip install xgboost` 已装。
5. **小数据直接堆 XGBoost 残差**：样本太少时残差过拟合。白盒先验先吃下主结构，残差只需补小头——这正是融合的优势，别让残差独自背全锅。
6. **单调方向写反**：`temp` 类"温度低=需药多"应写 `negative`（对温度变量而言低温对应高输出）。写反会让白盒+残差双重拧巴。
7. **忽略 `knee` 的语义**：膝点是"X 超过某值才开始贡献"，不是"最优值"。存款的年龄红利 35 岁前不累计，不是 35 岁最高。
8. **分布外外推不设 `range`**：审计的极端外推扫描依赖 `range`；不写则默认 `[knee,100]`，可能漏掉真实的低值越界。
9. **权重文件只存了 r 丢了 `.xgb.json`**：`--export-weights w.json` 会同时写 `w.xgb.json`（XGBoost 模型）。迁移时两个文件都要带，否则残差丢失。
10. **把合规当成 skill 的责任**：涉及资产/健康/个人字段须用户自行过 PIPL 与算法伦理审查；本 skill 仅为方法演示，不保证合规。
