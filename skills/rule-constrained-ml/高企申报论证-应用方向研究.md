# 规则约束下的机器学习：思想谱系、应用方向与高企申报论证素材

> 配套 skill：`rule-constrained-ml`（思想来源 Cheng Lou 的 handwired: https://github.com/chenglou/handwired）
> 用途：① 把本方法论讲清楚（它不新，但被工程化成可复现、可审计的交付流）；② 列举有实用价值的应用方向；③ 为"高新技术企业"申报提供"创新性 + 落地性"论证素材。

---

## 一、这个方法在学术/工业界"叫什么"（不夸大原创性）

本方法论不是凭空发明，而是四条成熟技术脉络的汇流，并取其交集做成了"规则优先、可读配方、零依赖、可独立审计"的工程封装：

| 称谓 | 核心主张 | 与本方法的对应 |
|------|----------|----------------|
| **灰箱模型 Grey-box**（机理-经验混合） | 已知物理/机理写死，未知部分交数据 | 直接对应"冻结结构、训练残差幅度" |
| **形状约束学习 Shape-constrained ML** | 强制单调/凸/信任等常识形状 | 对应 `sign: positive/negative` + ReLU 实现 |
| **可微编程 Differentiable Programming** | 把程序整体变成可求导对象 | handwired 的招牌，本 skill 沿用其哲学 |
| **PINNs / UDEs**（物理信息 ML） | 方程作正则项或残差项嵌入训练 | 同一思想在科学计算分支 |

**现实参照工具（说明这条路已被工业采用，非玩具）**：
- **XGBoost `monotone_constraints`**：免费、硬单调、零性能损耗，工业里按特征指定 `+1/-1` 方向[1]。
- **TensorFlow Lattice（Google 维护）**：Deep Lattice Networks，Google 用于**广告排序和贷款审批**，支持单调/凸/信任约束[2]。
- **约束神经网络保险定价**（CMNN、MonoKAN、ICEnet，2024–2026 热点）：监管强要求可解释+单调[3]。
- **污水厂灰箱预测控制**：2025 Aalborg 团队灰箱模型预测 N₂O/NH₄⁺，6h 预测拟合度 85%，仅 OLS 估参、无需手动标定——**加药系统的同领域先例**[4]。

> **关键定位（高企叙事要点）**：约束/单调技术本身不新；本方法的创新在于把"领域专家确定性知识 → 声明式配方 → 可微前向 → 仅训幅度 → 独立审计"做成了**一条可复现、可给审计师看、零重型依赖的交付流水线**，填补了"专家知识工程化、可审计化"的工具空白。

## 二、什么时候该用（决策树，诚实边界）

```
有"已知一定对"的领域结构(方向/安全/单调)? ──否──► 直接用回归/GBM/NN
        │是
有(小数据 | 要保安全硬约束 | 要可读可审计)? ──否──► 普通 ML 更合适
        │是
      ✅ 用本方法：冻结结构 + 只训幅度
```

| 该用 ✅ | 不该用 ❌ |
|---------|-----------|
| 知结构/方向/安全边界，只不知"幅度多大" | 无任何先验结构，只能从零学 |
| 样本少（几十~几千），从零训会过拟合 | 数据海量、无需先验 |
| 有安全/合规/单调硬约束（绝不越界） | 无约束需求，纯追精度 |
| 要可解释成一条人话规则给监管/客户 | 只要分数、不要理由 |
| 小数据冷启动，再逐步放开可训项 | 已有成熟黑盒且够好 |

## 三、应用方向（分三档，含"冻结/可训"映射）

### Tier A — 本机构自有业务（数据/领域在手，最该先做）

| 方向 | 冻结（白盒保底） | 可训（灰盒） | 锚点 |
|------|------------------|--------------|------|
| **AI 加药系统（旗舰）** | 安全上限 cap、投加上限、三药剂耦合化学计量骨架 | 投加曲线系数、按水质/流量微调增益 | 2025 灰箱污水控制[4]；本 skill `recipe_water_dosing.yaml` |
| **再生水定价 + 客户意向评级** | 量价反向单调（用越大单价越低）、地板价、评级门槛 | 折扣系数、各行业用水弹性 | 对接《意向单位名录》47 家 |
| **通沟污泥财务敏感性** | NPV/IRR 现金流结构、折旧/税率 | 处置单价、补贴、泥质波动成本系数 | 对接可行性研究可研 |
| **出水水质预警** | 物质守恒、去除机理骨架 | 动力学速率常数（随季节/菌种） | 同[4]，灰箱预测 6h 水质 |

### Tier B — 经典已验证领域（可借鉴论证）

| 方向 | 冻结 | 可训 | 为什么适合 |
|------|------|------|------------|
| 保险定价 | 年龄↑风险↑、免赔额↑保费↓ 单调；监管地板 | 各因子幅度 | 监管强要求可解释+单调[3] |
| 个性化用药剂量（PK/PD） | 体重/肾功能→剂量 单调；不超安全上限 | 个体代谢系数 | 安全关键，黑盒不可用 |
| 精准农业灌溉 | 温度↑/湿度↓→需水↑；不超田间持水 | 作物系数 | "浇花例子"的真实版 |
| 建筑能耗/碳排核算 | 面积/工况→能耗 单调；不负数 | 设备效率系数 | 强制披露、需可审计 |

### Tier C — 有意思的延伸

| 方向 | 一句话 |
|------|--------|
| 信贷/风控评分 | EU AI Act 要求"重大影响"决策可解释——硬单调+可读规则正好合规 |
| 设备预测性维护（RUL） | 磨损物理冻结，退化速率从运行数据学 |
| 带护栏的推荐/排序 | "预算以上绝不推""好评越多对评分越敏感（信任约束）" |
| 教育成效预测 | 出勤/作业→成效 单调，幅度从成绩数据训 |

## 四、回到本机构：最该落地的 4 个（结合现有项目）

1. **加药系统是天然旗舰**——同时满足"结构已知、安全硬约束、样本相对少、需可解释"四条件，且与高企申报专利方向（三药剂耦合、边缘计算、中国水质模型）咬合。
2. **再生水定价/评级**直接复用已有《意向单位名录》，把"评级高/年用水大→折扣/优先"业务逻辑冻结，只训弹性系数。
3. **通沟污泥可研**把现金流结构冻结、不确定单价/补贴当可训项——是现有手工"敏感性分析"的自动化、可审计版。
4. **出水水质预警**套用 2025 灰箱论文，做出"机理骨架 + 数据微调"预警模型，作高企示范应用。

## 五、它不适合什么（诚实边界，避免申报夸大）

- **纯感知/生成任务**（图像、语音、NLP）：无"明规则结构"可言，硬套是削足适履。
- **数据极大且结构未知**：直接 GBM/深度学习更省事，约束反而拖累。
- **实时毫秒级控制**：生成模型是纯 Python 前向，未上 GPU/编译优化；真正硬实时需接 C/WebGPU（handwired 原项目才做那层）。

## 六、与主流方案的差异（避免被质疑"和 XGBoost 单调约束重复"）

| 维度 | XGBoost 单调约束 | TensorFlow Lattice | **本 skill（rule-constrained-ml）** |
|------|------------------|--------------------|--------------------------------------|
| 约束类型 | 单调 | 单调/凸/信任 | 单调 + 地板 + **安全上限 cap** + 膝点 + 加性结构 |
| 输出形态 | 树集成（黑盒） | 查表网络（半黑盒） | **可读规则 + 系数**（白盒） |
| 依赖 | 重（XGBoost） | 重（TensorFlow） | **零重型依赖**（仅标准库） |
| 审计 | 需解析模型 | 需解析模型 | **训练/审计工具分离，审计师只看 recipe+系数** |
| 适用规模 | 大数据 | 中大数据 | **小数据冷启动 + 安全关键** |

> 定位差异清晰：**不是"更准的模型"，而是"更可控、可审计、小数据友好的混合建模交付流"**，特别适合受监管、要安全底线、领域专家知识密集的水务/工业场景。

## 七、高企申报可引用的创新点（候选）

1. **领域知识工程化**：把专家"明规则"（结构+符号+地板+上限）结构化、可机器编译。
2. **安全约束结构冻结**：用 `relu/-relu/min` 在结构层保证符号域与硬上限，训练无法绕过（对应加药"绝不超量/停泵"）。
3. **训练-审计分离**：生成的模型与独立审计工具解耦，满足合规复核"不见训练代码也能验证约束"。
4. **小数据冷启动**：从正确结构出发只训少数幅度系数，几十~几百样本即可，优于从零学。
5. **零重型依赖可复现**：标准库即可运行，便于边缘部署（契合"边缘计算"专利方向）。
