# 四、常见坑（pitfalls）

1. **把"明规则"和"训练系数"混淆**
   明规则 = 结构 + 符号 + 地板 + 膝点（冻结、不含数字）；训练系数 = 幅度（会变）。
   若把具体数字写进 recipe，就失去了"从确定结构出发"的意义。recipe 只声明符号/约束。

2. **滥用 `free` 符号**
   `free` 放弃符号保障，等于把该因素交回纯数据——可能翻向、破坏可解释性。
   仅在确实无任何先验方向时才用；否则宁可写 `positive`/`negative` 把方向钉死。

3. **约束模型同分布 MSE 略高，误判为"更差"**
   约束模型拒绝拟合会破坏结构/符号的噪声，MSE 可能略高于无约束回归。
   这是为安全/可解释付的代价，不是缺陷。看 MSE 要同时看约束审计是否通过。

4. **无约束回归在分布外越界**
   未加地板的纯回归在极端外推时可能给出负存款/负剂量等物理不可能的输出。
   这正是冻结地板(floor)与符号的价值——用 `rcml_validate.py` 做越界扫描复核。

5. **标签数据缺失或来源不合规**
   方法唯一缺不了的输入是 `(x, y_true)` 配对标签。没有标签，结构再漂亮也无从训练。
   涉及个人/敏感字段（如本例"存款"）须过《个人信息保护法》与算法伦理审查，
   本 skill 仅为方法演示，不可直接用于对个人画像。

6. **ordinal 当 numeric 用，丢失膝点语义**
   有序档（如收入能级 1..5）应用 `ordinal`(编码 max(x-base,0))，不要当连续 `numeric`，
   否则训练会把"档差"误解为线性斜率，且失去"从基准档起算"的直觉。

7. **膝点(knee)位置拍脑袋**
   `knee: 35` 这类结构假设应有领域依据。位置定错，模型从错误处开始累积/转折。
   若不确定膝点，先把它设为 `free` 或做敏感度分析，确认后再冻结。

8. **数据未覆盖边界，审计"假通过"**
   单调性/越界扫描在配方声明的 `range` 内做；若真实数据从未触及边界，
   冻结约束的"实战有效性"未被验证。采集数据要刻意覆盖极端值。

9. **过度自信"规则即真相"**
   冻结结构来自人的先验，先验可能错。定期用新数据复核：若可训练系数长期顶到
   约束边界（如 negative 系数持续接近 0），说明该因素方向假设可能要重新审视。

10. **忘记导出/留存权重**
    训练产物是权重 json（幅度系数），不是模型文件本身。务必 `--export-weights`
    留存，配合 recipe 即可独立复现与审计（合规场景必备）。
