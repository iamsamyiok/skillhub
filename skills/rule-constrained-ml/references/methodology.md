# 二、通用方法（methodology）

## 何时该用本 skill（决策树）

```
你有一个待建模的系统
  │
  ├─ 没有任何先验结构, 只想拿到最好的拟合?
  │     → 直接用 回归 / 梯度提升 / 神经网络, 别用本 skill(更省事更准)
  │
  ├─ 有"已知一定对"的领域结构(方向/安全/单调性)?
  │     → ✅ 本 skill 的主场
  │
  ├─ 数据极少(几十~几百条), 从零训模型会过拟合?
  │     → ✅ 从正确结构出发只调几个数, 数据效率高
  │
  ├─ 输出必须满足硬约束(非负/单调/不越界), 黑盒给不了?
  │     → ✅ 冻结结构即可保证
  │
  └─ 结果要给人读/审计/解释成一条规则?
        → ✅ 产出仍是可读规则
```

一句话：**有先验结构 + (小数据 | 要保安全 | 要可解释) 时，本 skill 值钱；纯无结构拟合时，普通 ML 更合适。**

## 通用七步

**① 界定系统（建模）**
列出 N 个自变量（数值直接用；类别如"工种"做 one-hot 成若干 0/1 cell），明确 1 个因变量的物理含义与量纲。

**② 手写白盒程序（结构化假设）** —— *区别于普通 ML 的灵魂*
用领域知识写确定性程序：给定输入怎么算输出。离散判断用 ReLU 写连续算术（选择器），循环/状态写成加权求和。产出"你相信正确的结构"。

**③ 四分类（冻结 / 可训 / 受限 / 仅可微）** —— *最关键的设计决策*
能确定的一律冻结；没把握的幅度标为可训练；"方向确定但幅度未知且绝不能翻向"的标为受限（≤0 / 夹紧）；安全/单调性在结构层写死。

**④ 准备配对标签数据（(x, y_true)）**
这是唯一必须"采集"的东西。输入来自传感器/记录，真实值来自观测/人工标注/参考法。要覆盖边界以验证冻结约束未被打破。

**⑤ 编译为可微计算（本 skill 自动完成）**
把 `+`、`*`、ReLU 收集成前向图（生成代码 `forward`），自动获得可微性、地板、GPU 友好。

**⑥ 训练：只更新「可训练」那一类**
定义损失（如 MSE），反向传播，**仅对可训练旋钮求梯度并更新**；冻结项梯度不回传、受限项被夹紧。在未见样本上验证约束仍成立、输出合理（无负数/巨量）。

**⑦ 产出：一条被数据校准过的规则**
结果是"原规则 + 几个调好的系数"，可读、可审计、可解释。安全底线始终是你写的。

## 套路骨架（对照浇花/存款 demo）

```python
def forward(r, f):                 # ① 结构(白盒, 手写)
    d = r['base']
    for k in inputs: d += coef(r,k) * f[k]   # 各因素加和
    return max(d, FLOOR)           # 地板(冻结)

FROZEN    = {"threshold": 30}      # ③ 冻结: 写死不动
TRAINABLE = {"amount": 500.0}      # ③ 可训练: 经验初值, 待训
# ④ 数据: (x, y_true) 配对
# ⑥ 训练: 只更新 TRAINABLE, 冻结项梯度不回传
```

## agent 在七步中的角色

| 步 | agent 动作 | 人工关卡 |
|----|-----------|---------|
| 1-3 | 引导用户把领域知识落成 recipe（变量、符号、约束） | **G1**：明规则确认 |
| 4 | 提示标签从哪来、如何覆盖边界、合规风险 | **G2**：数据合规确认 |
| 5-6 | 运行 rcml_build + 训练，自动校验约束 | — |
| 7 | 用 rcml_validate 独立审计，填报告模板 | **G3**：交付确认 |

> agent 负责"从零到有"(生成代码/训练/校验)，人负责"从好看到能用"——尤其是明规则与数据合规这两道关，必须由人把关。
