# STE-ZH 技术文档写作规范

生成中文长文档时遵循 ASD-STE100（简化技术英语）原则的中文落地版：短句、主动语态、一词一物、精确量化。本规范在写作时生效，交付前用自带检查器验证达标。

## 写作铁律（生成时逐条遵守）

1. **短句，一句一事**。程序句不超过 40 字，描述句不超过 50 字，每句逗号不超过 4 个。
   - 反例：维修人员在完成拆卸作业之后需要对泵体进行目视检查并且记录检查数据然后提交。
   - 正例：维修人员拆卸泵体。目视检查泵体。记录检查数据并提交。

2. **主动语态，动词开头**。施动者做主语，动作动词开头。
   - 反例：管路由维修人员实施检查。
   - 正例：维修人员检查管路。

3. **禁名词化冗余**。删掉"对……进行/实施/予以/加以 + 动词"和"做出 + 名词"，直接用动词。
   - 反例：对阀门进行关闭操作；予以确认；做出总结。
   - 正例：关闭阀门；确认；总结。

4. **步骤句式**。编号步骤以动作动词开头（检查、断开、拧紧、测量、记录）；条件步骤写成"若……，则……"；步骤中禁用"请"。
   - 反例：1. 请操作人员把阀门弄到全开位置。
   - 正例：1. 打开阀门至全开位置。

5. **一词一物**。同一对象全文只用一个名称。动笔前先建术语表（见工作流），写作时严格执行。
   - 反例：拧紧螺栓，然后更换螺丝。（螺栓/螺丝混用）
   - 正例：统一用"螺栓"。

6. **精确量化**。数值 + 单位 + 公差范围；禁用"适量、大概、左右、若干、一堆"。
   - 反例：大概拧紧到 45 N·m 左右。
   - 正例：拧紧至 45 ± 2 N·m。

7. **缩略语首现定义**。格式：中文全称（缩略语）。IT/USB/API 等常用词可不定义；每份文档的缩略语总数尽量不超过 5 个。

8. **三级警示，全文统一用中文**，写明后果。警告 = 人身伤害；注意 = 设备损伤；说明 = 补充信息。信号词独立成行，冒号结尾。
   - 反例：小心烫伤！
   - 正例：警告：触碰排气管可致烫伤。

9. **单位**。使用 SI 单位，同一物理量全文只用一种写法（N·m、cm、MPa）；禁用公分、公尺、牛米。

10. **语气**。书面规范语。禁口语网语（搞定、弄好、立马、踩坑）、文言措辞（切记、切勿、务须、倘若）、双重否定（不能不、并非不）。

11. **标点**。分号不用于连接独立句，改成两句；括号只放缩略语、等价术语、单位换算，长补充说明移出括号另起一句。

12. **定语与名词串**。"的"链每句不超过 2 个；连续名词堆叠超过 14 字时用"的"或介词拆分，或收入术语表命名为固定术语。
    - 反例：检查水泵进水端机械密封件冷却冲洗管路节流孔板。
    - 正例：检查节流孔板。该孔板位于机械密封件的冷却冲洗管路上。

## 长文档骨架

按需取用，保持层级清晰：

```
# 文档标题
文档目的（2-3 句）+ 适用范围与读者

警告：……（人身风险，置顶）
注意：……（设备风险）

## 工具与材料
- 名称 规格 数量（列表，含量程）

## 作业步骤
1. 动词开头的一步一动作
2. ……
   若……，则……

## 验收标准
量化判据（数值 + 单位 + 公差）

## 故障排除
| 现象 | 原因 | 措施 |
```

## 生成工作流

1. **建术语表**：列出关键对象的唯一名称、单位写法、缩略语展开。术语表随文档交付（附在文末或单独文件）。
2. **按骨架分节写作**，逐节遵守铁律。
3. **自检**（Node 18+）：
   ```
   node <本 skill 目录>/check.js 草稿.md
   ```
4. **修订**：先清零"错误"级问题，再处理"建议"级；对照报告逐条修改原文。
5. **复检**至达标后交付。

## 验收标准（缺一不可）

- check.js 得分不低于 90，且"错误"级问题为 0
- 术语表与全文用词一致
- 步骤全部动词开头，警示全部符合三级格式

## 备注

- check.js 支持 `--min N` 参数调整及格线（默认 90）；退出码 0=达标、1=未达标、2=用法错误，可接入自动化流程。
- 规则体系为 ASD-STE100 原则的中文改编实践版，规则编号（L01–L17）为自拟编号，与 ASD 官方规范条号无逐条对应关系；官方完整规范请购买 ASD 原版。
